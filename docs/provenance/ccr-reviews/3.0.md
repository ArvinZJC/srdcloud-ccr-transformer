# CCR 3.0 Review Archive

Historical review results; see the [current reference](../ccr-fusion-compatibility.md) for active contracts and the [artifact register](gateway-artifacts.md) for published package identities. Release commits below are peeled tag commits. Review entries compare against the preceding reviewed version unless stated otherwise.

All reviews found the canonical Fusion boundary compatible and the vision shim still necessary. None established authenticated end-to-end chat, model discovery, vision/fallback, hosted search, custom MCP, canonical tool-result, or direct-request success. Startup checks and synthetic tests are identified separately; an omitted check is not a pass.

## 3.0.13 Review Evidence

- **Identity:** Compared 3.0.11 → 3.0.13 and published gateway 1.0.7 → 1.0.9, including source maps.
- **Relevant changes:** Gateway extraction, Fusion MCP proxy propagation, vision usage reporting, hosted search, routing, and Responses stream metadata preserved the integration contracts.
- **Decision:** No extension change.
- **Validation and limits:** Structural source/package comparison only; no installed-app request validation.

## 3.0.15 Review Evidence

- **Identity:** Compared 3.0.13 → 3.0.15 and gateway 1.0.9 → 1.0.12 source maps.
- **Relevant changes:** The new `standardRequest.text` field affects Responses. This extension already uses CCR's materialised body for that source, so its Anthropic-only projection needs no addition. Capability aliases, configuration refactoring, extended Fusion loops, media tooling, and logging remained compatible.
- **Decision:** No extension change.
- **Validation and limits:** Structural source/package comparison only; no installed-app request validation.

## 3.0.16 Review Evidence

- **Identity:** Installed 3.0.16; gateway remains 1.0.12. The single post-tag `main` commit changed only README content.
- **Relevant changes:** New permission/surface enforcement disables undeclared plugins before registration. Provider-name normalization remains compatible with the extension's capability-qualified identities.
- **Decision:** Added explicit access declarations for trusted code, app/status-route registration, core gateway configuration, and the then-present direct provider registration. The latter grants were removed in 3.0.17.
- **Validation and limits:** Source, installed-version, and saved-config inspection. After declaration repair and restart, fresh wrapper/module log markers and the status route confirmed startup only.

## 3.0.17 Review Evidence

- **Identity:** Local checkout matched the tag; installed 3.0.17 inspected. Gateway 1.0.12 → 1.0.14.
- **Relevant changes:** Advanced-serialization IPC rejects executable functions in wrapper registrations before gateway startup. Earlier releases used JSON transport, which silently discarded those redundant functions; their gateways already supported module loading.
- **Decision:** Kept only the serializable `modulePath` descriptor and gateway-process `createGatewayPlugin()` loading. Removed direct provider registration, its provider surface, and `core-provider-plugins` permission from the manifest and saved-config repair helper. This preserves the reviewed 3.0.11–3.0.16 loading path.
- **Validation and limits:** Source/bundle comparison and structured-clone regression reproduction. Restarted desktop service/status and fresh wrapper/module markers confirmed startup; authenticated requests remained untested.

## 3.0.18 Review Evidence

- **Identity:** Local `dev/3.1` matched the tag; installed 3.0.18. Gateway 1.0.14 → 1.0.15.
- **Relevant changes:** Published source-map changes were confined to `gateway/handler.ts` and `gateway/streaming-conversion.ts`: empty-output retry and optimistic streaming for native Anthropic and visible tool calls. Plugin loading, request hooks, and canonical types were unchanged.
- **Decision:** No extension change; response-path changes need no transformer response hook.
- **Validation and limits:** Source/package/version comparison and 150 local tests. Desktop was not running; startup and live traffic were unverified.

## 3.0.22 Review Evidence

- **Identity:** Installed 3.0.22; local `main` at `99f24806c6a2c660b16e53e95211c517448a6c90` was one commit ahead, changing sponsor links and an unrelated preset. Gateway 1.0.17 → 1.0.18.
- **Relevant changes:** Fusion adds vision fallback models/retries, media-reference instructions, and payload validation. Gateway updates cover Anthropic authorization, internal-tool result folding, multimodal references, optimistic tool-result delivery/keepalives, and Undici dispatch. The new wrapper request-transform surface is independent of this extension's registration.
- **Decision:** Extended the vision shim to inspect primary and fallback selectors, deduplicate SRDCloud models, and fail closed if any selected model is absent. No new registration permission or request-transformer change.
- **Validation and limits:** Source/package/bundle/saved-config comparison and local tests. Desktop was not running; startup and real vision fallback execution remained unverified.

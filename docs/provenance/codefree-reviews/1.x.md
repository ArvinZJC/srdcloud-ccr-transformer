## Shared Validation Boundary

From 1.5.1 onward, the reviewed 12-package matrices contain eight unique executables: macOS ARM64/x64, Windows ARM64/x64, Linux ARM64/x64 glibc, and Linux ARM64/x64 musl. The per-release entries distinguish semantic validation, tarball integrity checks, installed-artifact comparisons, local tests, and desktop startup checks. None establishes authenticated end-to-end chat, model discovery, or Fusion success; an omitted check is not a pass. Recovered authentication values and user-specific credentials are excluded throughout.

## 1.9.0 Review Evidence

- **Identity:** All 12 platform tarballs, both comparison wrappers, and the 1.8.0 macOS ARM64 baseline passed npm SHA-512 verification. Installed macOS ARM64 matched the published executable at `106856162` bytes, SHA-256 `e7bba045b17e60746961cf53fc15d7ade466759c70e62592fcb540ce48a1f35b`; installed wrapper metadata and scripts also matched. Both install scripts are unchanged from 1.8.0. See the [complete snapshot](artifacts/1.9.0.json).
- **Relevant changes:** Signing precedes encryption and refresh code, and refresh persistence accepts a credential-generation argument; the previous extractor rejected this layout. Chat and embedding requests add `codefreeClient: codefreeo`. Upstream guards writes and refresh completion against concurrent credential clearing using generations and pending-write tracking, but can retain rotated credentials in memory after ordinary persistence failure. Routing, session/model projection, subservice selection/removal, model-discovery mapping, encryption, refresh negotiation, expiry skew, signing input, and modern headers remain compatible.
- **Decision:** Adapted the extractor to the bounded layout and optional second persistence argument while retaining semantic checks. Both transformer entry paths emit the new marker; model discovery does not receive it. Updated default client identity to 1.9.0 while preserving explicit version and User-Agent overrides. Canonical Fusion projection and the extension’s stricter atomic, owner-only persistence requirement remain unchanged; no authentication-material migration or persistence relaxation was needed.
- **Validation and limits:** All eight executables passed the updated validator and yielded the same material as the fingerprint-verified 1.8.0 baseline. Regression coverage includes both layouts, malformed signing/token relationships, missing rotation/expiry checks, duplicates, excessive separation, and disconnected persistence arguments. All 157 tests, syntax and provenance checks passed. Restarted CCR gateway returned `ok: true` for this project’s module. Install hooks were not executed; auxiliary MCP semantics and authenticated chat, model discovery, and Fusion requests remain unverified.
